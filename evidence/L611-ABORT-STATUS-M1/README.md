# L611: preserve prior status when a count error discards a resumable list

This parent-authored correction addresses independent review L601-F1 at7ccc00f8. It is a preexisting shell-driver behavior, not a defect in L577/L592 numeric conversion. Original review FAIL and old receipts stay immutable.

Actual Bash distinguishes a failed request's status from the status restored when it discards a resumable script/stdin/interactive list. A nonzero preceding pipeline status is preserved for the next list; zero becomes1. An exact `-c` source instead terminates1. Numeric-invalid exit still ends2, valid exits retain their value and pipeline children cannot request parent exit/list abort.

Root cause: osh_exec correctly records the failed request as status1 and sets the session last status. The driver discarded the list without restoring the prior nonzero status. The fix belongs to the resumable shell-driver layer: snapshot before each pipeline, then restore only on parent abort when the source can resume. Snapshotting the whole input list would be wrong if an earlier command on the same line changed status. No executor/journal/raw API semantics, builtin conversion, parser, compiler or prompt-wait implementation is changed.
