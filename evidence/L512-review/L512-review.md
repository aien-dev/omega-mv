## Trace findings, L489 exact SHA above

**T1, HIGH, selected-field consent mismatch.** `tools/trace/share.mjs:18-29`. `fields` filters only metrics and receipts. With `preset=spans`, the output still includes raw producer number, sequence, training step, time tick, source/category/status, and other event metadata. `disclosures.privacy_surface.numeric_fields` lists only the chosen metric. An owner choosing `--fields loss` can therefore disclose workload structure they did not select, contrary to #611's field allowlist and estimated disclosure surface. Repro: `node /home/drakestapleton/workspace/targets/L512-review/trace-adversarial.mjs`; output shows fields `loss` while producer `4321`, sequence/time `987654321`, step `123456` appear. Bounded fix: explicitly define and expose mandatory span metadata in the preview/allowlist, or require separate affirmative selections for each metadata class; make disclosure listing match exact emitted fields and add a canary test. Keep the deterministic local-only boundary.

**T2, HIGH, unclean writer can be presented as complete.** `tools/trace/archive.mjs:42-52`, especially line 50. `readArchive` excludes `.writer.lock` from orphan/problems checks and can return `integrity=PASS` with a stale lock, although a process killed with queued events can leave no on-disk indication of those events. `tools/trace/share.mjs:6` then accepts that query for packaging. Repro: the same script creates a stale writer lock; read reports `PASS`, zero problems and package allowed. The synthetic stale lock is a boundary probe, not proof that the worker actually crashed. Impact: crash loss may be undisclosed as a normal complete archive, violating #608's unclean-shutdown/loss diagnosis and #611's loss disclosure. Bounded fix: recognize an uncleared writer session as `INCONCLUSIVE` with unknown loss extent; recover into a new archive with explicit disclosure and test real process termination at an enqueued-but-unacknowledged cut. Do not infer a precise drop count from a stale lock.

**T3, MEDIUM, interrupted purge silently leaves private segment bytes.** `tools/trace/archive.mjs:49-50,77-87`. Retention writes an index tombstone before unlinking a segment. If the process exits in that gap, a subsequent read ignores the still-present segment because its name is in the retained set, returns `PASS`, and ordinary retention has no active entry to delete. Repro: the same script appends a valid purge tombstone without unlinking the segment; the segment remains on disk and `readArchive` reports `PASS`, zero problems. Impact: the owner can believe a purge succeeded while private data remains in the archive directory. Bounded fix: during open/read/recovery, detect tombstoned files and either finish verified deletion with a durable acknowledgment or report `INCONCLUSIVE` and the residual file; add a termination cut after tombstone fsync.
