# OMEGA (a systems language and compute platform being implemented in handwritten, seeded `.om`)

> Omega aims at one inspectable path from a small seed through compiler, runtime and applications to machine execution. The seeded `.om` compiler, `seed/out/omc`, is rebuilt from a 408-byte hand-written loader (`seed0 -> hex1 -> asm2 -> om4 -> omc`). The default branch still holds substantial C (`src/`, the legacy OSC compiler, the reaction runtime, GB10 numerics) that is unfinished migration, not the final language. Research-grade; an Alpha plan or an open PR is not a qualified release.

Shared rules: read https://www.aienos.com/agents/RULES.md first. This file adds what is specific to this repository; where the two differ, this file wins here.

## Scope

- Applies to the whole repository.
- `seed/`: the seeded compiler chain (rungs 0 to 4, `seed/omc/omc.om`, host checks in `seed/host/`). The language is specified in `docs/one_layer/OMEGESE.md`.
- `om/`: Omega implementations behind C entry points (`om/sha256`, `om/blake3`), bound into the C build through the generated `src/omega_om_units.inc`.
- `src/`: existing core and the C compiler awaiting replacement (`src/compiler/`), the reaction runtime (`src/runtime/`), the host-only fabric interface (`src/fabric/`), the Physics Zero apparatus (`src/physics0/`).
- `spec/`, `docs/`: specifications. `tests/`: gate suites; `tests/gates/*.gate` are the manifests the DGX Spark judge runs. `tools/`: harnesses. `mk/`: make fragments included by the `Makefile`.
- `bench/prime_race/`, `calibration/`, `research/`, `doctrine/`: benchmark, Turing calibration, experiments, the Milestone 4 doctrine.
- `evidence/`: content-addressed receipts, additions only.
- `docs/migration/C-TO-OM-INVENTORY.md` lists the C that remains to be replaced.

## Installation

Needs an AArch64 Linux host with `gcc`, `make` and `sh`. CI runs host suites on `ubuntu-24.04-arm`, and `test-realize` compiles with `-march=armv8.6-a+dotprod+i8mm+sve`.

```bash
git clone https://github.com/aien-dev/omega-mv.git omega
cd omega
sh seed/omega-from-seed.sh   # or: make omega-from-seed
```

`omega-from-seed.sh` grows the compiler from `seed/rung0/seed0.hex` (the one outside step is `seed/rung0/load0.sh`, POSIX `printf`), has omc rebuild itself twice to identical bytes, and leaves it at `seed/out/omc` with its sha256 beside it. No C is on that path.

Some gates expect sibling checkouts next to this one: `../physics` (physics-mv) and `../aienos` for the pinned FORGE and kernel sources, `../aien-architecture` for the crumb tool, `../omega-bridge` for `om-units`. A step whose sibling is missing exits 3 with a message.

## Configuration

- `physics.lock`, `aienos.lock`, `argus.lock`: commits of the sibling sources the full build and some gates pin. `crumb.lock`: the aien-architecture commit the crumb tool is built from. `om/omega-bridge.lock`: the omega-bridge commit whose `src/native.om` generates `src/omega_om_units.inc`.
- `PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0` on `make` builds the host suites without a physics checkout.
- `OUT_DIR`: per-step build directory; `tests/gates/run.sh` sets it to `build/step-<name>`.
- `.aien/always` lists the gates every commit must pass (`CRUMB-VERIFY`, `OMEGA-EVIDENCE-IMMUTABLE`, `OMEGA-ZERO-DISK-SECRETS`); `.aien/verify.pub` is the Spark judge's public key.
- `AIEN_OMEGA_FP8_GROUPED_WAVE=1` and `AIEN_OMEGA_FP8_GROUPED_CTAS=n` change the GB10 FP8 grouped expert launch (off by default; see `README.md`).

## Usage

`tests/gates/run.sh <step>` is the one entry point for the local gates; each step runs the same command as the gate manifest that names it.

Host-only (no GPU):

```bash
sh seed/omega-from-seed.sh                                              # seeded omc, self-rebuild fixpoint
tests/gates/run.sh seed                                                 # OMEGA-SEED: fixpoint, seed/host/check.sh, IR comparison against the C oracles
tests/gates/run.sh om-units                                             # Omega units: binding regenerated byte for byte, SHA-256/BLAKE3 parity, mutants (needs ../omega-bridge)
make PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0 test-compiler-quick  # legacy C compiler, quick suite
make PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0 test-numeric-cpu     # E1 CPU numerics
make PHYSICS_DIR=/nonexistent PHYSICS_LOCK_CHECK=0 test-realize
tests/gates/run.sh zero-disk-secrets                                    # no plaintext .env files
tests/gates/run.sh crumb-verify                                         # crumbs match the tool pinned in crumb.lock (needs ../aien-architecture)
```

The `make test-*` targets are C/legacy compatibility checks, not commands for the seeded compiler; do not mix compiler binaries or relabel old receipts. The full omegatool build (`make`) links the physics repository at the commit in `physics.lock`.

Gates whose manifest lists `gb10` under `requires:` (for example the `*-silicon` gates) need the GB10 on the DGX Spark. Run them only there, one at a time, inside an authorized GPU window, and never kill one mid-run. Gates that list `bare_metal` or `operator` are not for a plain host checkout; leave them to the Spark judge or an operator.

## Conventions

- Language rule: `.om` is the only forward first-party implementation language. Implement and qualify each replacement, switch its consumers, then remove the superseded C/Rust/shell. Do not rename C to `.om`, label handwritten C as generated or vendored, or otherwise game the language statistics.
- Verdict words: PASS, FAIL, NOT_RUN, BLOCKED_HARDWARE, BLOCKED_OPERATOR, MISSING_IMPLEMENTATION. Host and emulator passes are never reported as hardware qualification; GB10 results are tied to the exact commit in each receipt.
- Receipts are content-addressed (`<name>.<sha256>.json`), name the exact commit and refuse a dirty tree. A rerun adds a file; it never replaces one.
- Some older milestone gate scripts rewrite their receipts in place. Do not run them on a clean checkout you mean to keep; prefer the `make test-*` targets and `tests/gates/run.sh`.
- No systemd. Offline, in-house builds.
- Crumbs: read a directory's `.crumb` before editing it. `crumb verify .` must pass; it fails when committed crumbs differ from what the pinned compiler writes. `.crumbignore` keeps the compiler out of `evidence/` and `build/`. Live coordination goes in `.crumb.local`, never committed.
- Credit work in `CONTRIBUTORS.md` in the same commit as the work.

## Safety and approvals

- Never modify, rename or delete an existing file under `evidence/`. `.github/workflows/evidence-immutable.yml` fails any pull request that does.
- Never overwrite failed experiments or old receipts.
- Preserve the native GPU work and its recorded OS and driver dependencies. Do not infer hardware or OS independence from removing a userspace library.
- GB10 work happens only on the DGX Spark in an authorized window. Ask before running anything that opens the GPU.
- A head that changes `.aien/`, `tests/gates/`, `.github/workflows/`, `.forgejo/` or `tools/aien-test/` is `BLOCKED_OPERATOR` and needs an operator run on the Spark. Ask before touching those paths.
- GitHub workflows (`aien-verification.yml`, `om-units-arm64.yml`) are advisory and build only pinned verifier tools; Alpha qualification happens on the Spark. External review is expected before merge. Open a pull request with the exact command you ran and its output.
