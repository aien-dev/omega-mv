# Omega code hosted by the retained Linux kernel

## Conclusion and status

This is an optional bounded native leaf ABI experiment, not a prerequisite for executing Omega policy in Linux and not an OS replacement. Existing function-mode code can already be called through a suitable kernel adapter; a continuation/effect-record design needs no new policy-language feature merely to represent its state machine. A Linux module callback already executes in kernel context: it needs Linux ABI/lifetime contracts, not a userspace-to-EL1 transition. The experiment proves a restricted normal-return slice, not the absence of other kernel-hosted implementations.

IMPLEMENTED and HOST_EXERCISED in this isolated checkout: experimental `kleaf` output uses a normal value/status return, removes the private trap runtime, rejects non-leaf/effectful source, and clears the allocated volatile register set on every return. A second first-party `.om` implementation in omega-bridge emits the exact configured kernel's instruction mapping, patchable-entry relocation and PAC property. Genuine `.om` admission/divide/full-register-pool fixtures executed in an unprivileged host process, and unchanged policy bytes were packaged into a single kbuild object. This is neither a complete kernel target nor an Omega GPU driver. Kernel execution, module link/modpost, loading, real tracing, IRQ, DMA and GPU behavior remain NOT_RUN.

No production pin, gate, runtime loader, kernel capability, device ownership, signing policy, service or boot path changed. No module was installed or loaded. This prototype is a proposal artifact, not a supported language capability or adopted trust path.

## Inspected public compiler and bridge scope

At the base compiler revision, `seed/omc/omc.om` emits Linux AArch64 executable images for program mode, or raw private-ABI words for function mode (`s_eof`, `eof_prog`, `writeout`). `resolve` resolves unit-local branches, not external ELF symbol relocations. Acyclic calls and six argument slots do not provide kernel object linkage or callback ABI support. The register pool (`poolc`) already excludes x18 and callee-saved registers, but `save` saves LR without kernel frame/PAC/SCS integration; `stkchk` only checks program-mode stacks. Function-mode local arrays can be far larger than a kernel stack. `finish` sends traps through `[x7,#16]`, relying on the private runtime.

Canonical bridge `docs/NATIVE-ABI.md:77-110` and `src/native.om:39` provide a restricted integer freestanding unit bridge. `tools/native:33-35,99-117` compiles its generated envelope into an object. This is external-toolchain object packaging, NOT compiler-native ET_REL support or a kernel ABI. The existing trampoline explicitly saves/restores d8-d15, uses x19 to restore SP after traps, and lacks kernel PAC/SCS integration. Kernel C compiler flags cannot repair embedded SIMD or opaque code bytes. Nonlocal SP restoration would also leave SCS unbalanced if protection were naively added to nested calls. A libc-string symbol allowlist is not a kernel-import contract.

The legacy C interface `src/compiler/osc_native.h:18-45` describes mmap/mprotect/copy execution of OSC-1 bytes, not a Linux kernel object backend. ResumeX86 also reports that compiler923 and bridge37 do not add native ET_REL: the former emits Linux executable/raw private-ABI code and the latter packages bytes into hosted shared objects. That last comparison is peer-supplied context, not a claim of independently exercising its unsettled worktree.

## Kernel-hosted implementation alternatives, independent of this optional leaf

The leaf is useful scalar policy code, not a driver replacement or migration prerequisite. Arrays, loops and stateful continuations cannot select kleaf. Two distinct paths must not be conflated:

1. Reuse existing function-mode arrays, bounded loops and internal calls for `.om` continuation/effect-record state machines. A generated primitive-only Linux adapter performs a checked request after the unit returns and resumes it with the result; no Linux resources reside in discarded Omega frames. This requires bridge/admission work, not arbitrary extern calls or a new language feature. Native stack/call/trap hardening still needs target-specific review; leaving a caller register untouched is not proof of protection of internal saved return addresses. An alternative direct-call profile would additionally need whole-call-graph stack/work budgets, kernel frame/PAC/SCS treatment and consistent normal/trap returns. Neither path may bypass kernel hardening or silently replace a production compiler pin.
2. Extend `aien-dev/omega-bridge` beyond the implemented experimental static instruction/metadata envelope with a kernel binding generator written in `.om`. Emit typed callback declarations, kernel structure/layout adapters and narrow effect primitives from reviewed declarations. Compile any generated adapters with matching kbuild flags and required tracing, sanitizers, hardening and symbol-version data. No handwritten C state machine or generic arbitrary-pointer import table. Macros/inlines must use checked generated adapters rather than presumed linker symbols. Those effect/callback bindings are not implemented by this leaf envelope.
3. Keep PCI probe/remove, protocol sequencing, error rollback, admission, request ownership and lifecycle decisions in `.om`. Kernel adapters may perform a declared Linux primitive and return a checked result; they must not decide boot order, retry/quarantine policy, GPU page-table policy or teardown order. If C does those decisions, the result remains a C driver with an Omega slice and must be labeled that way.
4. Preserve Linux resources and callback context. Initial kernel-host transport should run in process/workqueue or threaded-IRQ context with a narrow non-sleeping hard-IRQ top half. Register exact typed callbacks, hold module/device/work references, prevent new admissions before teardown, cancel and drain queued work and IRQs, prove device DMA idle/revoked, then unmap/unpin/free. No detach while callbacks, requests or DMA can reference memory; failure to prove idle means retain/quarantine, not reclaim. Hot-unplug and reset need their own explicit state transitions and failure evidence.
5. Native ET_REL emission is optional for the first real kernel unit: kbuild can package validated native instructions. A future `.om` object emitter would replace GNU assembly/object packaging and add symbol tables/relocations/module metadata. It would not replace Linux DMA/IRQ/lifecycle services or solve their safety semantics. General native extern imports are broader than needed and constitute a separate reviewed effect authority, not a shortcut around the bounded binding design.

### Concrete extension boundary for the stateful driver

Stateful sources need the existing bounded loops/views/helpers, not the scalar-only kleaf mode. A versioned binding manifest must declare entry signatures, process/threaded/hard-IRQ contexts, exact source/compiler/config custody, storage bounds and permitted effect IDs. The minimum continuation path validates requests at a generated adapter after each unit return; direct typed native calls are a separate compiler/effect extension, not required for that migration. In either case review whole-call-graph stack/work bounds and target frame/return protection, and enforce device/generation/range/ownership before real effects. Current scalar envelope output cannot manufacture that authority.

Every future effect must name its resource and failure semantics: device reference acquisition/release; context-bound allocation/free; DMA allocation/map/sync/unmap tied to exact device, size and direction; user-page pin/invalidation/unpin where the client contract requires it; IRQ mask/ack/synchronize; work scheduling/draining; and ordered MMIO. Generated code may implement a declared Linux ABI primitive, while the owning `.om` state machine decides sequencing, rollback, publication and quarantine. Resource tables reject stale generation and wrong-device/direction/context before effects, hold references through completion, and retire only after Linux and device quiescence. These bindings are not ordinary extern relocation.


### Proposed kernel transport contract, not adopted

Inputs are opaque owned resource identities with generation, device identity, size/direction and context, not arbitrary ulong values treated as authority. Snapshot -> pure Omega decision -> synchronized generation/ownership revalidation -> declared effect -> completion record. A stale snapshot cannot publish/submit a request. Kernel pointers, CPU virtual addresses, CPU physical addresses, DMA addresses and GPU virtual addresses remain distinct types/representations; no pointer casts or raw IOVA integers become ownership proof.

Kernel allocation wrappers declare sleeping/atomic contexts, enforce configured DMA masks, and check every mapping/allocation failure. Use Linux `dma_alloc_coherent` or streaming DMA APIs as appropriate; pair exact sizes, direction and device on free/unmap. Perform required CPU/device sync operations and DMA publish/acquire barriers; coherent memory does not eliminate ordering. Do not DMA from module image, stack or unapproved vmalloc storage. IOMMU mapping/isolation remains Linux-owned, not a reproduction of user VFIO ioctls or a direct privileged-register backend. [DMA API guide](https://docs.kernel.org/core-api/dma-api-howto.html).

For DMA of user pages, use `pin_user_pages*` and required `FOLL_LONGTERM` mode for long-lived pins, reject unsupported memory types, pair unpin and dirty accounting correctly, and handle invalidation/reset so the device stops before backing memory is released. Preserve the declared client DMA contract rather than silently dropping user-page support or substituting get_user_pages. These effects are not implemented or exercised by this leaf experiment. [Pinning guide](https://docs.kernel.org/core-api/pin_user_pages.html).

Use Linux IRQ APIs with exact shared-IRQ identity, correct source acknowledgement/masking and IRQ return types. No sleeping allocation or unbounded policy execution in hard IRQ context. Do not call `synchronize_irq` while holding a resource the handler requires; it may sleep and must run in appropriate context. Mask/stop the source and drain relevant IRQ/work completions before storage release. [Generic IRQ API](https://docs.kernel.org/core-api/genericirq.html).

### Typed effect proposal `linux-kunit/1` (PROPOSED, not supported syntax)

These are interface records and effect signatures, not invented currently accepted Omega words. Implementing their source in an isolated compiler branch does not itself require module-load permission. Enabling them in an admitted kernel unit requires compiler/bridge review and pinned custody; registering/loading/binding such a unit is a separate operator authorization.

**Capability representation.** `Ctx` identifies one retained Linux device, driver-owned storage generation and callback context. `Dma`, `Pins`, `Sg`, `Mmio`, `Irq` and `Work` are non-forgeable resource types, not aliases of ulong. Their runtime table entries carry kind, owning Ctx/device, generation, rights, live state, backing Linux reference and the inverse operation's original arguments. Source cannot cast integers/CPU VA/DMA address/GPU VA into a capability, export a kernel pointer, or manufacture rights. Bounds use checked subtraction and checked sizes. Copies of a borrowed view do not extend its lifetime; ownership tokens cannot be duplicated or survive retirement.

`Txn` is a scoped per-device lifetime/producer-lock lease. Its acquisition revalidates generation/admission while acquiring the correct kernel lock; reset/removal uses the same lifetime exclusion. Views and mutable queue data cannot escape it. No sleeping/wait/drain effect is permitted while holding a spinlock or from hard IRQ. Initial queue publication runs in process/workqueue/threaded-IRQ context under a declared non-hard-IRQ lock, with bounded copying and work. A source snapshot or a caller-supplied `sqcore=1` is never effect authority.

The AArch64 barrier source is exact: `arch/arm64/include/asm/barrier.h:67-69` defines full `dmb osh`, acquire `dmb oshld` and release `dmb oshst`; `asm/io.h:96-122` supplies read-side DMA barrier/dependency and write-side DMA barrier with readl/writel plumbing. These are not interchangeable with ordinary loads/stores, syscall boundaries, CPU-only C11 fences or SMC. Do not open the GPU to test these claims.

**Boot sequence interface.** `.om` owns construction, index/range/version checks, sequencer prevalidation and sequencing. Send is `Txn -> qstore payload -> qrel -> qpub -> qnotify`; receive is `qpeek -> validate bounds -> qacq -> qread bounded payload -> validate message -> qdone -> qgive -> optional notification`. Tokens bind transaction, range, publication epoch/index and generation; no direct index/doorbell write exists and ownership ends at publication/read completion. Epochs/generations never wrap into an old live identity; exhaustion refuses. Entire sequencer programs validate before any effect. Core reset/start/wait/resume needs an engine-specific capability declaring operation/register set/generation/bounded wait budget; generic MMIO writes cannot reset it. Unsupported actions refuse before write/pause. No integer boolean/raw callback supplies this capability. Reset invalidates queue generations and tokens.

**Lifetimes on failure/removal.** Published/Quarantined storage cannot be reclaimed on callback return or timeout. The quiescence witness binds engine/submission/fence epoch/generation and the reviewed `.om` stop/completion protocol, not a bare success integer; hardware qualification remains necessary. Before admitting DMA that could become quarantined, acquire the persistent module reference while an independently protected entry is executing, never first during unload failure handling (`include/linux/module.h:681-720`). A pre-unload control operation runs under an independent entry reference, closes admissions, masks sources, drains IRQ/work without lock inversion, and proves/revokes DMA before reclamation. On success it releases the persistent reference, returns, then the external owner releases its entry reference after module code has returned. A self-pin must not depend on module_exit to release itself. On failure retain storage/context/module pin and leave unload blocked. Quarantinable context and buffers must use explicit non-detach-managed allocation, not devm_* or dmam_*: device/module refs do not prevent devres release on detach. BAR access leases drain before unmap; device-object lifetime alone is insufficient.

## Non-Omega dependencies and replacement boundary

Observed experiment dependencies, not silently adopted production dependencies:

- Linux `7.0.0-1019-nvidia` kernel, headers/config and matching symbol-version data: retained OS, scheduling, memory/pinning, IOMMU/DMA, PCI/IRQ/module lifecycle. There is intentionally no replacement in this architecture; replacing Linux is outside the request.
- Seeded Omega compiler at the exact digests above: first-party `.om` implementation, unchanged base binary bootstraps prototype. Any production pin adoption requires reviewed custody, not overriding canonical bridge checks.
- GNU assembler/linker/binutils `2.42`: verification executable and static object packaging. An Omega native object/ELF emitter is the concrete future replacement for packaging, not for Linux services. No foreign runtime is linked into the host oracle.
- GCC `13.3.0`, Ubuntu `13.3.0-6ubuntu2~24.04.1`, and GNU Make `4.3`: exact-kernel kbuild and verification C oracle. Future generated kernel ABI adapters would retain this explicit build dependency until Omega supports native callback/object/metadata/hardening lowering. Any generated C must be emitted through the Omega bridge; the prototype has no production C adapter.
- Python `3.12.3`: verification orchestration only, not compiler/driver implementation, build runtime or installed module dependency. `oracle.S` and `leaf_oracle.c` are verification oracles. `omega_leaf.S` is generated by first-party `.om`; GNU assembly/object packaging remains the disclosed build dependency until an Omega object emitter exists.

## Material decisions and remaining review

No operator decision is needed before isolated source implementation/review of a continuation adapter or typed-effect proposal: that alone admits no privileged execution. The inspected leaf ABI/PAC/SCS/tracing constraints are established by source/object comparison, not operator guesses. Production adoption needs code review of the effect manifest, capability/lifetime enforcement and exact target/compiler/bridge custody; no active pin or trust path changes here. Actual module loading, device binding, unload/reset or NVIDIA displacement needs a separate authorized operator/device window. Preserve the client ABI and DMA/pinning contract rather than silently reducing scope. Driver ownership/packaging is outside this public compiler experiment; no extraction or rename is proposed.

Companion compiler, bridge and omega-harness changes are draft-only, pending review. Production pins remain unchanged; this proposal does not promote `kleaf` into the supported language or establish a kernel driver. Main can reproduce the host experiment and inspect its source, objects and negative controls without touching a module or device.
