# omega_bytes: run instruction words we wrote by hand

What it is: a small tool that takes a text file of raw machine instructions (hex numbers, one
instruction per line, comments allowed) and runs them, with as little software in between as we
can manage. It is the "go back to the bytes" tool (ledger L098).

- **CPU (`a64`)**: the words are placed in executable memory by the existing runner
  (`src/compiler/osc_native.c`) and called like a function with up to 6 numbers.
- **GPU (`gb10`)**: the words are handed, as written, to the existing in-repo chip launcher
  (`omega_gpu_execute` with the Blackwell backend). No NVIDIA compiler, no CUDA library, no
  cubin or ELF wrapper.

Before anything runs, every word must be named: CPU words by our own decoder
(`src/aarch64_decoder.c`), GPU words by the opcode table our own sm_121 encoder produces. A word
nobody can name is refused, and the tool stops.

The tool itself is written in C, which the L098 brief allows for now.

## What is proven, and where

| What | Where it ran | Result |
| --- | --- | --- |
| a*3-2 written as CPU words, 16 argument sets against C | real Spark CPU | PASS 16/16 |
| 64-element vector add as CPU words, 16 sets against C | real Spark CPU | PASS 16/16 |
| Unknown CPU word and unknown GPU opcode are refused | real Spark CPU | refused, as required |
| 1,048,576-element vector add as hand GPU words | GB10 chip | see `evidence/BYTES-0/` |

Receipts: `evidence/BYTES-0/host/` (CPU gates), `evidence/BYTES-0/offline-disasm/` (the hand GPU
words read back by a disassembler, matching what was meant), chip session and speed against the
273 GB/s memory limit in `evidence/BYTES-0/ceiling.md` once the chip run has happened.

## Use

```
make omega-bytes                      # build/omega_bytes/omega_bytes
make test-omega-bytes                 # CPU gates + refusal checks (no chip)
build/omega_bytes/omega_bytes a64 tools/omega_bytes/kernels/a64_mul3sub2.words 7
build/omega_bytes/omega_bytes check gb10 tools/omega_bytes/kernels/gb10_vadd_hand.words
quiet-measure flock /tmp/aien-gb10.lock tools/omega_bytes/run_chip.sh evidence/BYTES-0/<stamp>
```

Word files live in `kernels/`. `gb10_vadd_encoder.words` is generated by
`omega_bytes emit-encoder-vecadd` (the existing encoder's vector add); do not edit it by hand.
