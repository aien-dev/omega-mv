## Abstraction correspondence obligations

This model assumes one writer, atomic full-vector reservation, exact original operands, current-policy authorization, stable object identity, authoritative cleanup/recovery, one operation identity per client, and idempotent lost-ack retry. It abstracts all snapshot bytes and histories to two charges and phase. It does not establish these assumptions in omnet, capture arbitrary filesystem interference, power loss, repeated requests, epoch wrap, unlimited demand, scheduler fairness or liveness. Atomic commit/recovery are proof obligations for the authority/store owner. Defective split states model why an unfenced external effect cannot inherit snapshot atomicity. Native execution of this model is not source-to-consumer translation correspondence under #623. Runtime promotion is prohibited pending owner integration and independent concrete correspondence evidence.
