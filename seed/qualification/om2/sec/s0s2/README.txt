ASSUMPTIONS (where contract and errata are silent; each also stated next to its case)
A1 0 line 13 + erratum E10: blank lines (empty or only spaces) are skipped like notes when finding the
   om2 line, so s0-blank-first and s0-blank-spaces-first are OM-2 units (they run, exit 0); OM-1 still
   refuses them at the om2 line (pinned: error 16 at line 5). Lines with trailing text (om2 , om2 foo,
   om2 diag x, om2  diag, "  om2", OM2) are not the opt-in line: OM-1 units keeping the OM-1 result.
A2 OM-1 codes for OM-2-only constructs in OM-1 units (s0/w-*) are what the pinned compiler gives
   today; C1 (line 17) requires the candidate to keep them (line 14: recognised only in OM-2 units).
A3 s0-optin-diag-same: an om2 diag unit compiles to the same artifact as the same om2 unit (lines
   34-37 and 116: diag adds stderr records, stdout unchanged).
A4 OM-2 units keep OM-1 error codes for non-OM-2 failures (preamble line 5: additive; 2 line 59
   "both profiles, unchanged"). [ and { stay error 3 in OM-2 (line 62). Undeclared struct stays
   error 16, undeclared function error 3.
A5 Formatter tokens: TAB is whitespace (the OM-1 lexer accepts it); indentation is the leading run of
   spaces/tabs; a text literal is one token from " to the closing unescaped ". "Whitespace next to (
   or )" (E6 e) = a whitespace run whose left token ends in ( or ) or whose right token starts with
   ( or ); every such run is kept, every other inner run becomes one space, trailing runs are dropped
   (x3 `ret   (add y  x)` -> `ret   (add y x)`; x4 `z  = (  add y   x )` -> `z = (  add y x )`).
A6 Hex: the human line names the literal's line. 17+ digits is error 6 whether or not the value fits
   (r6-17small value 1, r6-17big 2^64): line 56 counts digits before the range rule applies.
A7 found for a token longer than 32 bytes holds its first 32 bytes (d-longtok; line 40 "at most 32").
A8 The record's line= equals the human line N (all exact s1 cases). For an EOF span after a final LF
   the line is the empty last line, col 1 (d-eof-noend), which is also OM-1's human line.
A9 An fmt CR error names the line holding the first CR (bad-cr: the note line of the rest, line 2).

OBSERVATIONS ON THE PINNED COMPILER (all re-checked by pinned.cases)
O1 0 line 14 "OM-1 refuses that line": true only when nothing earlier in OM-1's pass order fails.
   OMEGESE 9.2's names pass reads every fn signature before any body or top-level line, so an OM-2
   unit whose signature is not OM-1-clean is refused at the FIRST such fn line (error 16 for
   fresh / view T * / out / unknown type; error 5 for a trailing `inline`), not at the om2 line.
   Rule applied to every pinned expectation: refused at the om2 line iff all signatures are
   OM-1-clean. All s0 opt-in and q1 fixtures and every other OM-2 fixture in this lane are
   signature-clean except s1/d-unknown-sparam.om (opt-in at line 3, undeclared struct Pt in the
   line-4 signature), whose pinned case expects line 4, error 16.
O2 `ret add 1 2 3` is error 11 (ambiguous bare-number add, found before the extra token), not a
   tokens-left code. With a typed operand (`ret add x 2 3`) tokens left is error 5. Both are pinned.
O3 A line ending before an operand is complete is error 4 reported on the NEXT line when more input
   follows (`ret add x` then `end`: the end line), and on the same line at end of input without LF.
O4 OM-1 accepts CR (CR LF and a lone CR before LF) as whitespace; s0-om1-crlf pins it under C1. The
   CR refusal (2 line 66, E6 g) is formatter-only.
O5 Grouped and ungrouped forms (g0..g4) compile to byte-identical output under 734f0a39, and so do
   x1..x5 against their oracle fmt output when the om2 line is removed (dev check; only x5, an OM-1
   unit, is a delivered pinned case).
