Method notes
- sha_qual.c calls the raw omega2_* symbols so a nonzero status is printed (TRAP), never aborted on; the
  generated omega_api.h supplies sha256_ctx. sha_driver.c uses the generated sha256_* names (abort on
  nonzero status) and is the s5s7 driver the 16 sha-* rows of sec/s5s7/candidate.cases name.
- Random messages: splitmix64 (fixtures/PROVENANCE.txt). Message i of seed S has bytes
  rnd(S ^ (i << 20) ^ 0x5eed, len); len and the chunk plan come from splitmix64 seeded S*1000003+i.
  randcheck.py needs only the printed (S, i, len) to regenerate the bytes.
- big: 2^32+1000003 random bytes in one malloc (56 GiB available at run time, free -g in t2-big.txt);
  the oracle digest is sha256sum fed the same buffer through a pipe. bigzero reads 2^32+3 bytes of a
  PROT_READ MAP_NORESERVE anonymous mapping (zero page).
- entry.py: leakscan seeds only at word 0 (or its direct B). For export k the copy's word 0 is the B
  of word k re-based to byte 0; all other bytes are unchanged, so the scan starts where the binding
  enters export k (NATIVE-ABI.md "Multi-entry code": the binding branches to byte 4k).
- trace.py: data addresses are base(+offset or +index<<shift, with uxtw/sxtw) from the register file
  before the instruction and objdump's operand text for that word; post-index uses the base. Message
  fills run outside the traced segments; an untraced warm-up call (first call per thread maps the
  binding stack) and a priming stop make segment boundaries uniform. Negative controls: CONTROL=1
  (message B one byte longer) must differ in instructions and data; CONTROL=2 (message B at buf+64)
  must differ in data addresses only.
- stack.py: SP depth over each function's CFG from `sub/add sp, sp, #imm` (the only SP writes found;
  any other SP write, SP writeback, depth conflict, nonzero RET depth or call cycle aborts).
