# The machine ceiling map: how many bytes this box can move (L151, 2026-10-20)

Drake's question: "Information is not measured in tokens. How many bytes can that thing move?" This page answers it
for the DGX Spark we run on (host spark-b87b, NVIDIA GB10, GPU sm_121, 20 Arm cores, 128 GB unified LPDDR5X).
Every row has three numbers: what the maker says the part can do (with the quoted source), the best we measured
with our own code (with the raw file it came from), and the fraction between them. Anything we did not measure says
UNMEASURED; nothing on this page is estimated.

## Summary for Drake

- The one pipe that feeds almost everything is the shared memory: NVIDIA rates it at 273 GB/s. Our own GPU code
  read it at 245 GB/s (0.90 of the rating) and wrote it at 175 GB/s (0.64).
- **How much data can move at once, measured at once:** with the GPU, all 20 CPU cores and the disk all streaming
  during the same 30 seconds, the box moved **222 GB/s** in total (0.81 of the 273 GB/s memory rating):
  GPU 189 GB/s + CPU 23 GB/s + disk 10.5 GB/s. That is less than the GPU alone (228 GB/s): everything shares one
  memory pipe, so adding streams does not add bandwidth, it splits it. The GPU takes most of it; the CPU cores fell
  from about 72 GB/s to 23 GB/s while the GPU was streaming.
- Inside the GPU the walls are much higher: the GPU's L2 cache delivered 5.1 TB/s and the per-core shared memory
  14.4 TB/s. Data that stays on the chip moves 20 to 60 times faster than data that comes from memory.
- Arithmetic, measured with our kernels: 8-bit tensor math 237.5 trillion operations per second, 16-bit tensor
  math 118.8 trillion, plain 32-bit math 17.7 trillion (0.57 of NVIDIA's 31 trillion). NVIDIA publishes no
  dense 8-bit or 16-bit figure for this chip; the "207.7 TFLOPS" we quoted before was a magazine's measurement,
  and our own kernel beats it.
- The disk reads at 10.6 GB/s (0.67 of its link) and writes at 11.5 GB/s over an existing file (3.3 GB/s while
  the file is first created).
- The fast network card (ConnectX-7, 200 Gb/s) is not present on this boot: its two slots are powered down and
  empty. The 10 Gb/s Ethernet port is up but has no 10 Gb/s partner to test against: UNMEASURED.
- Energy: moving one byte from memory through the GPU costs about 0.20 nanojoules at the wall on top of the
  box's baseline (0.10 nJ by the GPU's own power sensor). The disk and CPU streams did not raise the wall reading
  past the meter's 10 W step, so for them we only have an upper bound.
- Every lane we run today is placed against its wall in the last section. The 27B decoder is the closest to its
  wall (0.80 of 273 GB/s, 0.89 of what our best GPU stream reached); prompt reading is the farthest
  (0.05 of the measured 8-bit tensor rate).

## How these numbers were taken

- One measurement window (spark-window `20261020T030919Z-9d9d5a`, 2026-10-20 03:46Z to 04:08Z) that held both the
  quiet lock and the GPU lock, so no other GPU job ran during the GPU rows and the 27B server was paused waiting
  for the lock. Other agents' CPU jobs kept running (load average 39 to 55 the whole time), so **CPU rows are
  under load**; GPU and memory rows had the GPU to themselves.
- Our own code only: CPU probes in C (`tools/machine_ceiling/mc_cpu.c`, `mc_disk.c`), GPU kernels generated by
  Omega's Blackwell code generator and launched through the driver-free launcher (`tests/gpu_ceiling_test.c`,
  `tests/gpu_tc_peak_test.c`, `tests/gpu_qmma_probe_test.c`, `tests/gpu_pf_mem_test.c`, `tests/gpu_l2_reuse_test.c`,
  `tests/gpu_launch_cost_test.c`). Every probe checks its own results; every row below had 0 wrong values.
- The run itself: `tools/machine_ceiling/session.sh` (phases gpu, concurrent, host) under `spark-window run`.
- Raw output: `evidence/MACHINE-CEILING-20261020/raw/`, file checksums in `evidence/MACHINE-CEILING-20261020/SHA256SUMS` (check with `sha256sum -c ../SHA256SUMS` from inside `raw/`; all 34 match).
  Built from omega `doc/machine-ceiling` with physics at `6d7cf0d4` (= `physics.lock`).
- Wall watts come from the UPS (`spark-sensors`, 2 s samples, 10 W steps). The UPS output also feeds whatever else
  is plugged into it, so wall watts are the whole UPS load, not the Spark alone. Baseline: 240 W with the GPU idle
  (receipt `raw/2026-10-19-l151-chip-quiet-baseline.json`).
- Every derived number has an aien-calc receipt id beside it.

## 3. The whole machine at once

Drake asked for "how much data can move at once", measured together, not added on paper. Three streams started at
the same second (`MC_START_AT`) inside one GPU-lock hold and ran for 30 s (`raw/all-at-once.txt`, `raw/cc-*.txt`):

| Stream | Alone | All at once |
|---|---|---|
| GPU reading memory (GPU-cached, 1.5 GB set) | 228.0 GB/s | 189.1 GB/s |
| 20 CPU cores reading memory (64 MB each) | 71.3 GB/s (30-round average, calc:c249a25f) | 22.7 GB/s (calc:e7991b26) |
| NVMe read into memory | 10.54 GB/s | 10.545 GB/s |
| **Total** | | **222.3 GB/s** (calc:e2b9a9f6), **0.814 of 273** (calc:a3c62418) |

What it means: the memory pipe is the one shared wall. Running more things at once did not move more bytes than
the GPU alone moved; it divided roughly the same total among them. The disk kept its full speed (it is small next
to the pipe). The CPU lost about two thirds of its rate to the GPU. Paths that do not touch the memory pipe (GPU L2,
GPU shared memory, CPU caches) add on top of this, but none of them carry data into or out of the chip.

## 5. Every lane against the walls

The binding wall is the one that runs out first. "Fraction" uses the maker's number where one exists and our own
best measured number otherwise. All lane numbers below are one stream (one request at a time); no lane has a
receipt at full concurrency yet, which is what section 3 says to expect: concurrent work splits the same pipe.

| Lane | Speed on record (source) | Binding wall | Fraction |
|---|---|---|---|

What it tells us: decoding is close to the memory wall already, so its remaining gain is in reading fewer bytes per
word (smaller weights, several requests per weight read, more words per verify pass). Prompt reading is at 5% of the
tensor wall, so that is where the largest unused capacity on the chip sits.
