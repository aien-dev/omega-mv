# C to Omega: the scoreboard

Drake's goal (2026-10-22): Omega replaces C in all our repos, and every replacement is built by the Omega
compiler we grew ourselves from the seed (seed0 -> hex1 -> asm2 -> om4 -> omc), never by the old
C-built tools. The old C stays only as a reference to compare against.

## How to read this page

- **C lines remaining**: the table below counts the C still in each repo's main branch. The goal is 0.
  It is recounted by `tools/c2om/inventory.sh` at every push.
- **Waves**: the work is done in four batches.
  1. The Omega toolchain itself (the compiler, its checker, the language front end). After wave 1,
     Omega is built by Omega and judged by an Omega checker.
  2. The rest of the omega repo that does plain whole-number work (no decimals, no GPU, no threads).
  3. Everything with decimals (floating point), the GPU, threads, and CUDApp. Separate item L419.
  4. The kernel (aienux), physics, atlas, benchmarks, interplane. Separate item L420.
- **Artifact**: one program or library, with the tests that go with it.
- **Checked by**: the existing test the replacement must pass with byte-for-byte the same results as the C.
  A replacement only counts when that test passes with the Omega build in place of the C build.
- **Needs**: the language features the seeded compiler must gain first. Each has a numbered request
  (FR-n) in `~/handoffs/omega-feature-requests.md`, owned by the language lane L408:
  FR-1 opening files, FR-2 records (structs) with exact byte layout, FR-3 programs split over several
  files, FR-4 decimals (floating point), FR-5 GPU and device calls, FR-6 threads, FR-7 libraries other
  languages call, FR-8 kernel-level hardware words, FR-9 Intel/AMD (x86-64) output, FR-10 reading the
  command line and environment, FR-11 starting other programs, FR-12 reading the clock.
  HAND means the file uses something the translator refuses on purpose (for example C's anything-goes
  argument lists or overlapping memory types); those parts get rewritten by hand under the Omega rules.

## How a replacement is proven

1. The C version is built by gcc from a pinned commit (the reference, kept forever under a git tag
   `c-oracle/<artifact>`).
2. The Omega version is built only by the seed-born compiler omc; the fingerprint (sha256) of that omc
   is written into every evidence file.
3. Both run every case of the artifact's tests. They must give the same bytes out: printed text, files
   written, exit codes. The harness counts cases run against cases written.
4. A deliberate one-word break in the Omega version must make the comparison fail (proof the check
   can see a difference).
5. Only then the C files leave the live tree and the build points at the Omega version.
