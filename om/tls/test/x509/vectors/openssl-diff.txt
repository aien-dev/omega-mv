store_intermediate_anchor x509=accept openssl=reject: every certificate in the store is a trust anchor (RFC 5280 6.1.1 d: name + key); openssl needs -partial_chain for a non-self-signed anchor
at_not_after x509=accept openssl=reject: RFC 5280 4.1.2.5 validity is inclusive of notAfter; OpenSSL 3.0 treats now == notAfter as expired
wildcard_partial x509=reject openssl=accept: partial-label wildcards (f*.wild.test) refused per task rule and RFC 6125 6.4.3 SHOULD NOT; openssl allows them by default
no_san x509=reject openssl=accept: no subject CN fallback (RFC 6125 6.4.4 / CA/B BR require SAN); openssl falls back to the CN (CN equals the host only by test construction: host lNoSAN)
name_constraints_critical x509=reject openssl=accept: nameConstraints not implemented, so a critical one is refused (RFC 5280 4.2: unrecognized critical extension); openssl implements it and the name is permitted
depth_8_intermediates x509=reject openssl=accept: at most 8 non-anchor certificates (leaf + 7 intermediates); openssl default depth is 100
leaf_is_ca x509=reject openssl=accept: a CA certificate (cA TRUE) is not accepted as the server leaf; openssl sslserver purpose allows it
leaf_ku_no_digsig x509=reject openssl=accept: TLS 1.3 signs with the leaf key (CertificateVerify) so keyUsage must include digitalSignature; openssl sslserver also accepts keyEncipherment
rsa_1024_leaf x509=reject openssl=accept: RSA moduli below 2048 bits refused; OpenSSL 3.0 security level 1 (80 bits) accepts 1024
sha1_signed x509=reject openssl=accept: only SHA-256/384/512 signatures allowed; OpenSSL 3.0 verify at the default level accepts sha1WithRSAEncryption
rsassa_pss_key x509=reject openssl=accept: only rsaEncryption and id-ecPublicKey P-256/P-384 keys supported (TLS 1.3 rsa_pss_rsae_* schemes); id-RSASSA-PSS keys refused
ed25519_key x509=reject openssl=accept: Ed25519 keys not supported by this client (no ed25519 module in om/tls)
